}

10. Delete user
DELETE /api/users/:id

Flujo recomendado en Android:
1. Probar GET /health al abrir configuracion o pantalla de debug.
2. Registrar usuario con POST /api/register.
3. Hacer login con POST /api/login.
4. Guardar token JWT en SharedPreferences o DataStore.
5. Enviar Bearer token solo para PATCH /api/users/:id/password.
6. Guardar tambien user.id de login o register para consultar profile y user.

Campos utiles para data classes:
- LoginRequest: email, password
- RegisterRequest: nombre, apellido, usuario, password, fotoBase64, telefono, correo, fechaNac, genero
- StandardResponse: httpCode, message
- LoginBody: token, user
- LoginUser: id, email
- RegisterUser: id, nombre, apellido, usuario
- Profile: id, userId, fotoBase64, telefono, fechaNac, genero, createdAt, updatedAt

Notas:
- Si login devuelve invalid credentials, primero debes registrar el usuario.
- Si register devuelve error por duplicado, limpia tablas o usa otro email/usuario.
- Para pruebas locales en emulador Android usa http://10.0.2.2:3000/ como base URL.
- Para produccion usa https://202407391.aplicacionesweb2026.com/
